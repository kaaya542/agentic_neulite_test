# イオンチャネルの追加

[設計](../../../docs/architecture.md)を読み、既存機構と対象の式・ゲートの冪・温度補正・配置を比較する。

## 仕様と検証

- 目的、数式・MOD・論文の版を特定する。BMTK/Allenの資産を調べ、出典を確認する。
- 未指定の科学的条件だけを根拠・影響とともに相談し、[仕様](../../../docs/extension_spec_template.md)にまとめる。
- 参照式、電圧固定時の解析解、元MODから期待値を定める。C実装から期待値を作らない。
- 初期化、定常値・時定数、ゲート更新、電流・面積・単位、無効時回帰を検証する。必要に応じて特異点・濃度依存性も扱う。

## 実装

- vanillaまたは既存flavorをコピーし、派生元を記録する。
- bionetliteの機構名・パラメータ・列順を、Cの列数・列挙・配列・初期化・更新・電流と揃える。
- 入力検証はbionetlite、カーネルの入力時換算は`popl_func.h`へ置く。未対応の値や機構はエラーにする。
- 入力を再生成し、クリーンビルドして実際のC計算まで確認する。合格に合わせて基準を緩めない。

## 結果

同じ刺激での追加前後の膜電位、新チャネル・既存チャネル電流を、全時間とスパイク付近の図・元データで示す。単位・符号・条件を明記し、同一チャネルの比較には共通の軸を使う。電流比を発火への寄与率と解釈しない。

電圧・ゲート・Ca濃度の記録時点を揃え、観測の有無で膜電位・発火が変わらないことを確認する。保存済み電圧からの推定と実行時の記録を区別する。再現コマンド、比較誤差、回帰結果、検証範囲を添える。

Kv1_1には[仕様](../../../docs/extensions/kv1_1.md)、`test/kv1_1/verify.py`、[電流記録](../../../docs/extensions/kv1_1-recording.md)を使う。他の機構では期待値・記録列・式への接続を作り直す。
